# אור בראשית: גרסה לאתר אמיתי ב־Vercel

האתר המלא, עם העוזר החכם **ארי** שעונה בעזרת Gemini.
מפתח ה־API נשמר רק בהגדרות של Vercel ואף פעם לא מגיע לדפדפן של הגולשים.

## מה יש בתיקייה

| קובץ | מה הוא עושה |
| --- | --- |
| `index.html` | האתר עצמו: דף הפתיחה, הקולקציה, הסל, כל הדפים והצ'אט עם ארי |
| `api/chat.js` | פונקציית השרת: מקבלת את השיחה מהאתר, שולחת ל־Gemini ומחזירה תשובה |
| `lib/assistant-rules.js` | ההוראות של ארי והקטלוג שהוא מכיר. כאן מעדכנים מחירים ומוצרים עבורו |
| `img/` | תמונות המוצרים (WebP מכווץ) |
| `.env.example` | דוגמה לשמות משתני הסביבה (בלי ערכים) |
| `firebase-config.js` | חיבור האזור האישי ל־Firebase, ורשימת המיילים של המנהלים |
| `firestore.rules` | כללי האבטחה של מסד הנתונים (מדביקים ב־Firebase) |
| `tools/` | סקריפטי הבנייה של `index.html` (לא עולים לאתר) |

## האזור האישי (Firebase)

באזור האישי הלקוחות נכנסים עם Google או עם קישור שנשלח למייל (בלי סיסמה), ורואים את ההזמנות שלהם עם סטטוס, פרטים וכתובות שמורים, ומועדפים. הסל שלהם נשמר בין מכשירים. בעמוד `#/admin` המנהל מעדכן סטטוס להזמנות.

עד שמחברים את Firebase, האתר עובד כרגיל, ובאזור האישי כתוב שהוא "בדרך".

### הפעלה (פעם אחת, כ־10 דקות)

1. **פרויקט:** נכנסים ל־[console.firebase.google.com](https://console.firebase.google.com), לוחצים **Add project**, ונותנים שם (למשל `or-bereshit`). Google Analytics לא חובה.
2. **אפליקציית Web:** בדף הפרויקט לוחצים על סמל **`</>`**, נותנים שם, ולוחצים **Register app**. מעתיקים את האובייקט `firebaseConfig` שמופיע.
3. **כניסה:** ב־**Build → Authentication → Get started**:
   - **Sign-in method → Google → Enable**, בוחרים מייל תמיכה, **Save**.
   - **Sign-in method → Email/Password → Enable**, ומפעילים גם **Email link (passwordless sign-in)**. **Save**.
   - **Settings → Authorized domains → Add domain:** `orbereshit.vercel.app` (ואם יהיה דומיין משלכם, גם אותו).
4. **מסד נתונים:** ב־**Build → Firestore Database → Create database**, בוחרים אזור באירופה (למשל `eur3`), ו־**Production mode**.
5. **כללי אבטחה:** ב־Firestore → **Rules**, מוחקים את מה שיש, מדביקים את כל התוכן של `firestore.rules`, ולוחצים **Publish**.
6. **חיבור האתר:** פותחים את `firebase-config.js` ומחליפים את `window.FIREBASE_CONFIG = null;` באובייקט מסעיף 2, בצורה:
   `window.FIREBASE_CONFIG = { apiKey: "…", authDomain: "…", projectId: "…", storageBucket: "…", messagingSenderId: "…", appId: "…" };`
   הערכים האלה ציבוריים מטבעם. הגישה לנתונים מוגנת על ידי כללי האבטחה ורשימת הדומיינים המאושרים.
7. **מנהלים:** ב־`firebase-config.js` וגם ב־`firestore.rules` (בפונקציה `isAdmin`) רשום המייל שיכול לנהל הזמנות. המנהל נכנס עם Google או עם קישור שנשלח לכתובת הזו. אם רוצים מייל אחר לניהול, מחליפים בשני המקומות ומפרסמים שוב את הכללים.
8. שומרים, מעלים ל־GitHub, ו־Vercel מעדכן את האתר.

### איך זה עובד בהזמנה

כשלקוח מחובר לוחץ "שליחת הזמנה לוואטסאפ", ההודעה כוללת מספר הזמנה (למשל `OB-3K9QA7`), וההזמנה נשמרת אצלו באזור האישי בסטטוס **התקבלה**. התשלום עדיין מתואם בוואטסאפ, והסכומים בהזמנה הם מה שהלקוח ראה בסל. בודקים אותם מול ההודעה לפני שמאשרים.

## לפני הכל: מפתח חדש

המפתח שנשלח בצ'אט נחשף, ולכן:

1. נכנסים ל־[Google AI Studio → API keys](https://aistudio.google.com/apikey).
2. מוחקים את המפתח הישן.
3. יוצרים מפתח חדש ושומרים אותו אצלכם. **לא מדביקים אותו בקוד, בצ'אט או ב־GitHub.**

## העלאה ל־Vercel

### אפשרות א׳: דרך GitHub (מומלץ)

1. יוצרים מאגר חדש ב־GitHub ומעלים אליו את כל התיקייה הזו.
2. ב־[vercel.com/new](https://vercel.com/new) בוחרים את המאגר ולוחצים **Import**. אין צורך לשנות הגדרות בנייה.
3. לפני **Deploy** (או אחריו, ב־**Settings → Environment Variables**) מוסיפים:
   - `GEMINI_API_KEY` = המפתח החדש, מסומן ל־Production ול־Preview.
   - `GEMINI_MODEL` (לא חובה): שם מודל אחר, אם רוצים. ברירת המחדל היא `gemini-2.5-flash`.
4. אם הוספתם את המשתנה אחרי העלאה: **Deployments → Redeploy**, כדי שהשרת יקרא אותו.

### אפשרות ב׳: משורת הפקודה

```bash
npm i -g vercel
```

```bash
vercel
```

ואז מוסיפים את המפתח:

```bash
vercel env add GEMINI_API_KEY
```

ומעלים לגרסה הציבורית:

```bash
vercel --prod
```

## בדיקה

פותחים את כתובת האתר, לוחצים **צ'אט עם ארי** ושואלים משהו, למשל ״מה מתאים לחנוכת בית?״.

- **ארי עונה:** הכל מחובר.
- **מופיע ״העוזר החכם לא זמין כרגע״:** המפתח לא הוגדר, או שלא בוצע Redeploy אחרי שהוגדר.
- **מופיע ״משהו השתבש בחיבור״:** המפתח לא תקין, או ששם המודל ב־`GEMINI_MODEL` לא קיים. אפשר לראות את הפרטים ב־Vercel תחת **Logs**.

## בדיקה מקומית במחשב

מעתיקים את `.env.example` לקובץ בשם `.env.local`, ממלאים בו את המפתח, ואז:

```bash
vercel dev
```

הקובץ `.env.local` לא יעלה ל־GitHub (הוא ב־`.gitignore`).

## הגנות שכבר בנויות

- **המפתח מוגן:** הוא נקרא רק בשרת, ולא מופיע בקוד של הדף.
- **ההוראות שמורות בשרת:** הדפדפן שולח רק את השיחה, כך שאי אפשר לשנות לארי את התפקיד או להשתמש בשרת כצ'אטבוט כללי על חשבונכם.
- **הגבלות שימוש:**
  - עד 20 הודעות בשיחה, ועד 1,500 תווים להודעה.
  - עד 30 פניות ל־10 דקות מאותה כתובת. זו הגבלה בסיסית בזיכרון של השרת, שמאטה שימוש לרעה אבל לא חוסמת לגמרי.
  - כדאי להגדיר גם תקרת תקציב ב־Google Cloud על המפתח.
- **בדיקת פעולות:** ארי יכול רק להוסיף לסל מוצר קיים ולפתוח עמוד קיים. כל בקשה אחרת מהמודל נדחית בשרת.

## כשמשנים מוצרים או מחירים

מעדכנים בשני מקומות:

1. `PRODUCTS` בתוך `index.html` (מה שהגולשים רואים). התמונות נמצאות בתיקייה `img`.
2. `CATALOG` בתוך `lib/assistant-rules.js` (מה שארי יודע).
